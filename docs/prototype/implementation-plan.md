# Hackathon implementation plan

## Status and delivery principle

This is a proposed plan, not evidence that implementation has started. Build the thinnest safe end-to-end journey first: capture → category/confidence/correction → approved guidance → indicative price → participating location → recovery record/QR → recycler handoff/weight → processing evidence/review → journey dashboard. Expand polish only after that path works with controlled data and failure states.

Dependencies identify logical order, not a mandated project-management tool. Responsible disciplines are roles; named owners remain to be assigned.

## Suggested increments

1. **Walking skeleton:** Manually selected category and approved placeholder-structure response, one controlled location, record/QR, handoff, processing, dashboard—without pretending incomplete services are real.
2. **AI-assisted journey:** Add evaluated vision suggestion/confidence and controlled LLM transformation only after governance inputs exist.
3. **Offline resilience:** Add local persistence, cached governed content, idempotent sync, conflicts, and visible states.
4. **Review and polish:** Add flags/reviewer flow, status-separated aggregates, accessibility/language/device fixes, observability, rehearsal, and backup demo.

Each increment remains honest about simulation and uses no unapproved safety facts or real personal/business data.

## Critical-path decisions

Before implementation: select runtime/workspace through ADRs; inspect dataset rights/annotations; accept category/state/contracts; assign safety/card/language approvers; approve fictional demo locations/prices; decide hackathon identity/access approach, storage and provider boundaries; select supported devices; and obtain organiser submission requirements.

## Scope control

When time is constrained, protect the complete evidence journey, grounding, offline status, accessibility essentials, and truthful limitations. Defer optional audio, broader analytics/directory, edge inference, extra categories/languages, advanced fraud detection, and every real payment/regulatory integration before cutting required evidence or safety controls.
